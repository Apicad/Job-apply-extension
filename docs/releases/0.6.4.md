# Job Apply Assistant 0.6.4 — review guide

This release improves application-answer relevance and keeps unresolved review notes visible. It is part of the ongoing Job Apply Assistant project.

## Changes to review

- Before inserting an AI answer, check the essential parts of supported writing questions. An experience list alone cannot answer a work-style preference. Technology durations must be explicit; employment dates are insufficient. Proudest-project and built-from-scratch claims require saved evidence.
- Keep unresolved writing-question cards in local application-scoped history across Autofill runs and browser sessions. Existing answers are never overwritten to remove a warning.
- Replace old warnings only after a complete supported replacement is verified in an empty field, or after the user explicitly acknowledges resolving every item and the current question is uniquely identified and nonempty.
- Show scanning, saved-detail filling and AI-answer stages, plus the current question. Verified fills retain the brief green pulse. Reduced-motion preferences are respected; no artificial typing delay or extra input events are introduced.
- Present the repository as an ongoing project. Keep original plans locally and preserve existing Git history. Exclude tests, research notes, reports and planning documents from new GitHub snapshots as requested.

## Owner review checklist

Use fictional practice data or a draft you have authorized. Do not submit an application.

- [ ] Without a saved work-style preference, an unrelated experience list stays out of the empty answer box and the missing preference appears in the sidebar.
- [ ] Running Autofill again preserves unresolved notes and any existing answers.
- [ ] Reloading the extension does not lose application review history.
- [ ] Mark resolved requires explicit acknowledgement; an empty or ambiguous field is refused.
- [ ] After correcting an answer and marking it resolved, another run does not restore that resolved card while the field remains populated.
- [ ] The progress stages are understandable and the application is never submitted automatically.

Record your own observations in the GitHub pull request. The assistant must wait for the owner's explicit approval before merging.

## Limits

These are conservative checks for the currently supported question types, not a general semantic correctness guarantee. They may flag valid wording for manual review. The technology-duration format is deliberately constrained. Existing answer text is preserved, not automatically rewritten or semantically reevaluated. Human acknowledgement records a review; it is not independent proof that a claim is true. Current installation still requires unpacked Chrome setup and a local AI helper. Original planning and audit directories retain historical names for compatibility.

Automated test source is retained locally, so the GitHub review includes validation results but cannot reproduce the full test suite from a clone. Application compilation and production builds remain reproducible.
